# Intl-first internationalization

temday does not publish `zh-CN`, `fr`, or other locale tables. `localeData` connects locale selection to the date API; month names, weekdays, and localized formats are generated by the host `Intl` implementation at runtime.

That means the number of supported languages does not grow the application bundle: temday imports one generic locale plugin whether the app uses one language or twenty.

## Minimal setup

```ts
import temday from 'temday';
import localeData from 'temday/plugin/localeData';

temday.extend(localeData, { locale: 'zh-CN' });

const release = temday('2026-08-31T13:04:00Z');
release.format('YYYY-MMMM-DD[ day ]dddd');
```

Use brackets for application copy so it cannot collide with tokens.

## Load locale (Node.js) {#load-node}

Node reads locale data from its ICU-backed `Intl`. Install `localeData` with a BCP 47 locale tag; temday has no locale table to import.

```ts
temday.extend(localeData, { locale: 'zh-CN' });
```

## Load locale (browser) {#load-browser}

Modern browsers expose month and weekday names through native `Intl`. In older environments, load `temday/polyfill` according to the application policy; locale data still comes from host ICU.

## Change locale (global) {#change-global-locale}

Install the plugin once, then update temday when the application locale changes.

```ts
function setApplicationLocale(code: string) {
  i18n.setLocale(code);
  temday.locale(code);
}

setApplicationLocale('ja-JP');
```

## Change locale (instance) {#change-instance-locale}

For simultaneous locales, set the locale on an instance instead of changing the factory default.

```ts
const event = temday('2026-08-31');
event.locale('en-US').format('MMMM DD, YYYY');
event.locale('zh-CN').format('YYYY年MMMMDD日');
event.locale('ar-EG').format('DD MMMM YYYY');
```

## Current locale {#current-locale}

```ts
temday.locale();
temday('2026-08-31').locale();
```

## List months and weekdays {#list-months-and-weekdays}

```ts
const data = temday().localeData();
const months = Array.from({ length: 12 }, (_, index) => data.month(index));
const weekdays = Array.from({ length: 7 }, (_, index) => data.weekday(index));
```

## Locale properties {#locale-properties}

`localeData()` returns the active `LocaleProvider`: `code`, `month()`, `weekday()`, `ordinal()`, `meridiem()`, `format()`, and `firstDayOfWeek()`.

## Application-owned locale modules

The default `Intl` provider ships no temday locale table. If a product needs custom months, week starts, or terminology, its i18n system can own language modules and load them as it chooses.

```ts
import createIntlLocaleProvider from 'temday/locale/intl';

const providers = new Map();
temday.extend(localeData, {
  locale: 'en-US',
  provider: (code) => providers.get(code) ?? createIntlLocaleProvider(code),
});

async function switchLocale(code: string) {
  const { default: provider } = await import(`./i18n/date/${code}.ts`);
  providers.set(code, provider);
  temday.locale(code);
}
```

temday does not manage dynamic imports or guess a language list. Vue I18n, i18next, FormatJS, or a custom i18n layer controls code splitting; temday asks the active provider for display data.

`localeData` handles named display tokens (`MMM`, `MMMM`, `dd`, `ddd`, `dddd`) and localized aliases from `localizedFormat`. It does not treat language names as text-date parsing rules.
