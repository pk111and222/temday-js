# Intl-first 国际化

temday 不随包发布 `zh-CN`、`fr` 等语言表。`localeData` 只负责把语言选择接入日期 API；月份、星期和本地化格式由宿主的 `Intl` 在运行时生成。

这让语言数量不会增加应用 bundle：无论使用一种还是二十种语言，temday 只会引入一次通用 locale 插件。

## 最小接入

```ts
import temday from 'temday';
import localeData from 'temday/plugin/localeData';

temday.extend(localeData, { locale: 'zh-CN' });

const release = temday('2026-08-31T13:04:00Z');
release.format('YYYY-MMMM-DD[日] dddd');
// 2026-八月-31日 星期日
```

`[日]` 是字面文本。建议始终用方括号包裹文案，避免它与未来 token 冲突。

## 加载语言配置 (Node.js) {#load-node}

Node 使用自身 ICU 的 `Intl` 数据。安装 `localeData` 并给出 BCP 47 语言码即可，无需导入 temday 的语言表。

```ts
temday.extend(localeData, { locale: 'zh-CN' });
```

## 加载语言配置 (浏览器) {#load-browser}

现代浏览器同样通过原生 `Intl` 提供月份与星期名称。需要支持旧运行时时，再按应用策略加载 `temday/polyfill`；locale 数据仍由宿主 ICU 提供。

## 改变语言配置 (全局) {#change-global-locale}

安装插件一次即可。语言切换时只更新 temday 的默认 locale：

```ts
import { i18n } from './i18n';

function setApplicationLocale(code: string) {
  i18n.setLocale(code);
  temday.locale(code);
}

setApplicationLocale('ja-JP');
temday('2026-08-31').format('YYYY年MMMMDD日');
// 2026年8月31日
```

## 改变语言配置 (当前实例) {#change-instance-locale}

一个界面同时展示多种语言时，不要改全局默认值；在实例上指定 locale：

```ts
const event = temday('2026-08-31');

event.locale('en-US').format('MMMM DD, YYYY');
event.locale('zh-CN').format('YYYY年MMMMDD日');
event.locale('ar-EG').format('DD MMMM YYYY');
```

## 查看当前语言配置 {#current-locale}

```ts
temday.locale();
temday('2026-08-31').locale();
```

## 列出当前语言的月份和周 {#list-months-and-weekdays}

```ts
const data = temday().localeData();
const months = Array.from({ length: 12 }, (_, index) => data.month(index));
const weekdays = Array.from({ length: 7 }, (_, index) => data.weekday(index));
```

## 获取语言配置的属性 {#locale-properties}

`localeData()` 返回当前 `LocaleProvider`，包含 `code`、`month()`、`weekday()`、`ordinal()`、`meridiem()`、`format()` 与 `firstDayOfWeek()`。

## “引用哪些语言，就打包哪些语言”

使用默认 `Intl` provider 时，没有 temday 语言包需要打包：语言数据来自浏览器或 Node 的 ICU。应用 bundle 始终只有 `localeData` 的通用逻辑。

如果产品需要自定义月份、周起始日或专有译法，请将语言模块放在你自己的 i18n 目录，并通过 provider 按应用策略加载：

```ts
import temday from 'temday';
import localeData from 'temday/plugin/localeData';
import createIntlLocaleProvider from 'temday/locale/intl';

const providers = new Map();
temday.extend(localeData, {
  locale: 'en-US',
  provider: (code) => providers.get(code) ?? createIntlLocaleProvider(code),
});

async function switchLocale(code: string) {
  // 由应用的 bundler 决定拆包与缓存策略。
  const { default: provider } = await import(`./i18n/date/${code}.ts`);
  providers.set(code, provider);
  temday.locale(code);
}
```

这里 temday 不管理动态 import，也不会猜测用户需要哪些语言；它只在格式化时向当前 provider 查询数据。这使 Vue I18n、i18next、FormatJS 或自研 i18n 都能控制自己的按语言拆包策略。

## 不应该使用的 token

`localeData` 只用于展示 `MMM`、`MMMM`、`dd`、`ddd`、`dddd`，并配合 `localizedFormat` 提供 `L`、`LL`、`LLLL`。不要把这些 token 用作日期解析格式；中文文字日期等输入应先由应用规范化，或改用数值 `customParseFormat`。
